# The Mac app

The native macOS app (SwiftUI, not Catalyst) over the shared views in `../Shared/`.

| File | What |
|---|---|
| `SHAFTApp.swift` | the entry point: one window, the menu commands including "Check for Updates…" in the app menu, the Settings window (⌘,: Shared's `SettingsView`, including Appearance before pairing); applies the device theme through `NSApp.appearance` at launch and on change; the app delegate (the push token, notification clicks that bring the window forward on that chat, no banner for the chat in the window in front, `/` to the composer, the app kept running with its window closed) |
| `UpdateFeed.swift`, `AppUpdates.swift` | self-update with Sparkle, only in a build carrying a trusted feed: the Developer ID download made by `Scripts/release-mac.sh`; Settings' "Check for updates automatically" and "Check Now", shown before pairing too; an everyday build says it does not update itself. Feed availability is tested in `../macOSTests/` |
| `MacRoot.swift` | the window, on `canvas`: the instances in the sidebar on `elevated`, the chat (earlier chats pushed over it), the documents as an inspector (`ChatShell`), at 320 pt and draggable as far as the window leaves the chat its 380, the sidebar giving way to them under 1000 pt of window width (and they to it, when it is asked for there); the chat column's minimum as the split views need it (`splitChatMinimum`); `MacState`, which the menus share; `MacPresence` (the chat long-polls and is marked seen while the window shows it, in front or beside another app's window); `shaft://chat/<instance>` |
| `MacChrome.swift` | the room the chat's title has beside the toolbar's buttons, the inspector's header in its part of the toolbar (back or close, the page's name, its actions), a sheet's title on the gutter; why the text views refuse Writing Tools (`MacChrome.writingToolsAffordance`) |
| `MacCommands.swift` | the menu bar: File → New Message (⌘N), New Chat (⇧⌘N); Chat → Stop (⌘.), End (⇧⌘E), Queue after reply (⌘↩; Send when idle), Send for the Next Cycle, Documents (⌥⌘D), Earlier Chats (⇧⌘Y), Next/Previous Chat (⌥↓/⌥↑), Reload (⌘R); the sidebar and inspector toggles. `MacMenu` publishes what they may do |
| `MacTextViews.swift` | the Mac halves of Shared's text seams: the composer's field (an `NSTextView`: Return sends, Shift/Option-Return a new line, Cmd-Return queues, files pasted or dropped are attached) and the selectable text of Select text (↩ Reply and Comment in its right-click menu) |
| `MessageTextView.swift` | a message's text (`MessageNSView`): one string in one layout, shown by a linked `NSTextView` per segment, so a selection runs from a paragraph through a code block into the next. Code blocks and tables sit in rounded `elevated` blocks that scroll sideways (`MessageBlockView`; language and Copy in a code block's header), with ↩ Reply / + Quote beside a selection and a right-click menu (↩ Reply on the selection, the system's Copy and Look Up, Copy message, Reply to message, Copy code, the thumbs) |
| `SelectionReplyButton.swift` | the ↩ Reply / + Quote button beside a selection: a solid `accent` fill of its own, because the system's push bezel is see-through on macOS 26 and this button floats on the text; takes its own clicks when its frame runs past its parent's bounds |
| `MenuAction.swift` | the text views' own menu items (a closure each) and the read-only text's right-click menu without Cut, Paste, Font and Spelling. Tested in `../macOSTests/` |
| `MarkdownAttributed.swift` | Markdown (and the operator's own text) as AppKit text, type per the design: headings, lists, task boxes, code with its syntax colours (SHAFTKit's `CodeTokens`), quotes, tables (`NSTextTable`, numbers to the right), links; explicit reading scale for body, headings, code and tables; its split into segments, what they measure at a width (`Measure`), where a segment ends (`MessageTextContainer`) and the colour tokens as `NSColor`s (`MacColor`). Tested in `../macOSTests/`, which links `Design.swift` and `Appearance.swift` in |
| `MacDevSession.swift`, `MacDevDriver.swift` | Debug builds only: a run from a terminal against the fixture server (`SHAFT_DEV_DIR`, `SHAFT_DEV_PAIR`, `SHAFT_DEV_PRESENCE`) and a script that drives it (`SHAFT_DEV_DRIVE`); `../README.md` says how |

The session forwards every confirmed server badge to `AppModel.setBadge`, including while the window is closed.
It updates the notification badge and the Dock label together, and clears them when unpaired.
